## 已决定

### 独立存储空间

应用存储统一使用 `ai-image-studio` 标识，不读取、迁移或回退到旧项目的数据库及存储键，也不主动删除旧数据库和存储键。存储与备份结构由本 fork 独立维护，保留外部输入所需的校验。

### 不要 Agent 模式

应用只保留画廊工作流，彻底移除 Agent 的对话、分支、工具编排、网络搜索、独立配置及相关界面和存储。不保留隐藏开关或兼容实现，不跟进或恢复上游 Agent 功能。画廊使用的 Images API、多供应商、参考图、遮罩、画板和批量生成继续保留。

此次移除允许重置 AI Image Studio 的全部本地数据：IndexedDB 从版本 3 升至 4，首次升级时重建任务、图片和缩略图仓库；本地状态从版本 2 升至 3，旧版本直接恢复默认值。后续刷新正常保留新数据。ZIP 备份格式升至 4，仅支持新版备份，不兼容旧备份。此决定覆盖本 fork 旧版数据结构与备份格式沿用约定，不涉及原项目的存储空间。

### 不要桌面客户端

不引入、不恢复上游 v0.8 的 Windows 客户端。包括 `src-tauri`、安装包、自绘标题栏、应用内更新、系统代理、数据目录、SQLite 与图片文件存储、由 Rust 发请求、MCP 服务。原因是维护者明确不要桌面端，而 v0.8.0 到 v0.8.4 混在同一条 `main` 上，不能整支合并。

### 不要 CLI 与 Skill

上游 v0.8.2 的 CLI `gpt-image-playground` 和随附 Skill，是给 Claude Code、Codex 等本机工具用的。它操作的是正在运行的 Windows 客户端：应用必须开着，生图、历史和设置才会进那个客户端。安装入口也在客户端的「设置 → Skill」。

所以它不是一条能单独搬进网页版的能力，随客户端一起拒绝。

### 不要 @ 图片引用

移除提示词中的 `@` 选图菜单、图片引用胶囊、右键插入引用、引用编号跟随和请求转换。参考图仍按列表全部发送，用户直接用自然语言描述各图用途。画板评论保留，独立使用不带 `@` 的评论胶囊。不兼容或迁移旧图片引用记录。

### 去掉赞助和推广

已移除应用内赞助入口、赞助弹窗及其状态和触发逻辑，删除 README 中的商业推广与赞助支持区块，以及仓库内的推广预置文件。只删推广，不删功能，保留供应商接入、配置导入、用户已有数据、非商业链接和来源与许可声明。

### 简化生图接入

保留 OpenAI Images API、Gemini generateContent、xAI Images（均支持对应协议的兼容接口）与自定义 HTTP 接口。彻底移除内置 sub2api 异步接入和 fal.ai 接入，包括专用请求、队列恢复、参数限制、SDK 依赖及创建入口，不跟进恢复这两种内置适配。

接入统一使用 `connectionId`：内置接入为 `openai-images`、`gemini-generate-content`、`xai-images`，自定义 HTTP 接口引用 `customConnections` 中的定义 ID。不再保留服务商类型、API 模式及旧版单配置字段，不读取或转换旧结构。自定义 HTTP 接口的同步、异步能力继续保留。

此次统一允许重置全部本地数据：IndexedDB 升至版本 5，本地状态升至版本 4，旧版本直接清空或恢复默认值。ZIP 备份格式升至 5，配置分享格式升至 2，仅支持新结构。部署文件、查询参数与自定义接口提示词同步使用新字段。

### 生成参数与首页显示

首页只保留常用操作，数量、质量等参数放入“更多设置”，OpenAI 默认显示数量和质量，Gemini 默认显示数量。每个 API 配置单独设置高级参数默认值和首页显示项，切换配置时记住各自的选择。隐藏参数使用配置默认值，不代表停止发送；历史任务重试使用任务保存的参数。

同一配置包含多个模型时，设置页提供各模型支持的参数和选项，首页仍按当前所选模型显示与发送，避免模型列表顺序导致高级参数无法配置。

内置接入遵循所选官方协议，自定义接口根据当前生成或编辑模板引用的变量提供首页参数，固定值在模板中设置。已有的 Base64 兼容开关保留，其额外添加字段的行为明确标注。不根据提示词改写或缺少改写信息推断渠道为 Codex CLI。

接口默认以 `default` 表示，发送请求时省略对应字段，明确指定的 `auto` 等值仍按选择发送。原生背景提供接口默认、不透明和透明三档；本地去背景单独使用开关。中间预览图默认请求零张。本次结构调整不做旧配置迁移或旧参数转换。

### Gemini 生图

新增独立的 Gemini generateContent 接入，使用 x-goog-api-key 认证、contents 输入和 imageConfig 图像配置。支持文生图、参考图编辑、比例与分辨率、多次生成（每个任务最多两个请求并发）、参数记忆和历史重试。内联请求在本应用中限制为 20 MiB。

首页共用尺寸入口，Gemini 的比例和分辨率独立保存，支持按模型选择思考强度和设置默认值。仅提供本地去背景，不发送 OpenAI 的质量、审核、格式、压缩或兼容参数。首版不提供蒙版、流式、搜索和连续对话，不引入 Interactions 或 Imagen 接口。第三方需兼容所选协议；不自动切换格式重试。

Gemini 2.5 和第一代 Nano Banana 不提供可调分辨率，始终省略 imageSize。识别 Nano Banana 2、2.1／2-1、Pro 和 Lite 别名；失败时保存原始响应，部分失败按输出槽位查看，保留两请求并发和内联请求大小限制。

### Grok 生图

新增独立的 `xai-images` 接入，使用 Bearer 认证和 JSON 请求，支持文生图、最多五张参考图编辑、比例、1K／2K 分辨率、单次一至十张、Base64 结果和部署代理。Grok Imagine Image 2.0 提供 auto、low、medium 质量；其他模型省略质量字段。默认参数省略，配置切换、默认值、分享、部署预置和历史重试沿用现有结构。仅支持本地去背景，不提供蒙版、流式或连续对话，不主动启用 xAI 的 deferred 异步模式。

### 独立画板标注与新输出格式

参考图上的笔画保存为独立透明图层，原图保持不变；支持清空、撤销、历史复用、重试和备份。OpenAI Images 接入在 GPT Image 2.5 及以上、未开启 Codex CLI 兼容且没有蒙版时，把首图标注作为 markup 发送；其他接入与其余参考图在请求前合成。标注与蒙版不同时作为原生参数发送。

GPT Image 2.6 及以上提供复杂度、SVG 和 GIF 输出，首页显示与默认值按配置控制。SVG 仅支持无参考图的文生图，数量固定为一；SVG 编写模型为可选配置，留空不发送 svg 对象。GIF 可带参考图，提供二至十六帧和每帧二十至两千毫秒的设置，时长按十毫秒取整，不支持蒙版。SVG／GIF 不发送流式、预览或压缩字段，不进行本地去背景。

SVG／GIF 原始字节和扩展名在保存、下载及备份中保留，作为参考图使用时转成 PNG，GIF 只取第一帧；SVG 缺少宽高时按 viewBox 补齐尺寸。新增可选字段兼容已有数据，不提升数据库版本或清空记录。

### 不要版本检查

应用不请求 GitHub Release，不在顶栏提示新版本，也不提供更新日志弹窗。版本号只用于构建、关于页显示和发布记录，发布由维护者手动决定。上游的更新弹窗、版本历史和忽略版本等改动不再跟进。

### 图片改存二进制

IndexedDB 升至版本 6，原图和缩略图在库内以 Blob 保存，读取接口仍返回 dataUrl，备份格式不变。与之前的结构调整一样，升级时直接重建任务、图片和缩略图仓库，不迁移版本 5 的字符串记录。
